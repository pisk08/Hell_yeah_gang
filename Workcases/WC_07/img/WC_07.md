## 1. Планування задач в ОС

### Основні функції планувальника задач

Планувальник задач (Task Scheduler / Job Scheduler) — це компонент ОС, який автоматизує виконання процесів.

#### Основні функції:
- Автоматичний запуск програм у заданий час
- Періодичне виконання задач (щоденно, щотижнево тощо)
- Запуск при подіях (вхід користувача, запуск системи)
- Керування ресурсами (пріоритети, черги)
- Логування виконання задач
- Обробка помилок і повторні спроби

### Порівняння: Windows та Linux

| Windows (Task Scheduler) | Linux (Cron) |
| :--- | :--- |
| Графічний інтерфейс (GUI) | Робота через CLI (без GUI) |
| Гнучкі тригери (події, час, стан системи) | Дуже гнучкий синтаксис |
| Підтримка умов (живлення, мережа) | Легка інтеграція зі скриптами |
| Інтеграція з системними службами | Простота для масових задач |

## 2. Cron в Linux

### Принцип роботи

Cron читає файл crontab, де описані задачі у форматі:

```
* * * * * команда
│ │ │ │ │
│ │ │ │ └── день тижня (0-7)
│ │ │ └──── місяць
│ │ └────── день місяця
│ └──────── година
└────────── хвилина
```

### Основні команди

#### Редагувати задачі

```Bash
crontab -e
```

#### Переглянути задачі

```Bash
crontab -l
```

#### Видалити задачі

```Bash
crontab -r
```

### Приклади налаштування

#### Виконання у визначений час (08:00)

```Bash
0 8 * * * /home/petryshaka/script.sh
```

#### Двічі на день (08:00 і 18:00)

```Bash
0 8,18 * * * /home/petryshaka/script.sh
```

#### Тільки у будні з 8 до 18 (щогодини)

```Bash
0 8-18 * * 1-5 /home/petryshaka/script.sh
```

#### Різні періоди

| Частота | Cron |
| :--- | :--- |
| Щогодини | `0 * * * *` |
| Щодня | `0 0 * * *` |
| Щомісяця | `0 0 1 * *` |
| Щороку | `0 0 1 1 *` |
| При запуску | `@reboot` |

### Приклади задач

#### Очистка каталогу

```Bash
0 3 * * * rm -rf /tmp/*
```

#### Очистка каталогу

```Bash
0 2 * * * tar -czf /backup/home.tar.gz /home/petryshaka
```

#### Очистка каталогу

```Bash
0 23 * * * shutdown now
```

## 3. Реалізація задач через Cron та systemd timer

У якості альтернативи планувальнику задач Cron було використано systemd timers.

На першому етапі було відкрито редактор планувальника Cron за допомогою команди:
crontab -e

<img src="img/01.png">

У файлі crontab було створено декілька завдань для автоматичного виконання, зокрема резервне копіювання файлів, очищення директорій та запуск скриптів.

<img src="img/02.png">

Далі було створено сервісний файл systemd:
/etc/systemd/system/my_backup.service

У даному файлі описано виконання команди, яка записує інформацію у лог-файл із зазначенням часу виконання.

<img src="img/03.png">

Після цього було створено таймер:
/etc/systemd/system/my_backup.timer

У таймері задано розклад виконання задачі двічі на день (09:00 та 21:00), а також параметр Persistent=true.

<img src="img/04.png">

Після створення конфігурацій було виконано перезавантаження systemd та активацію таймера за допомогою команд:
systemctl daemon-reload
systemctl enable my_backup.timer
systemctl start my_backup.timer

<img src="img/05.png">

Для перевірки було використано команду:
systemctl list-timers

У результаті у списку відображається таймер my_backup.timer, що підтверджує його коректну роботу.

Таким чином, systemd timers можуть ефективно використовуватись як альтернатива Cron для автоматизації задач у системі.

## Словник (Vocabulary)

1. Scheduler — system component that manages and executes tasks at specified times or events.

2. Task Scheduler — tool (especially in Windows) used to automate the execution of programs and scripts.

3. Event-based scheduling — running tasks in response to specific system events (system startup, user login).

4. Cron — time-based job scheduler in Unix/Linux systems used to execute commands automatically at specified intervals.

5. Systemd timer — unit in systemd used to schedule tasks as an alternative to Cron.

6. Anacron — Linux utility that executes scheduled tasks that were missed while the system was powered off.

7. Time-based scheduling — running tasks at predefined times or intervals.

8. Crontab — configuration file where users define scheduled tasks for Cron.

9. Cron daemon (crond) — background service that runs and executes scheduled Cron jobs.

10. Automation — use of systems to perform tasks automatically without human intervention.

## Висновок (Conclusion)
In this work, task scheduling in operating systems was examined, focusing on its importance for automating routine processes and increasing overall system efficiency. The core capabilities of scheduling tools were considered, such as executing commands at predefined times, running tasks periodically, and performing system operations without direct user involvement.

A comparison between Windows and Linux revealed that both operating systems support task scheduling; however, Linux provides greater flexibility and precision through tools like Cron, while Windows relies more on a graphical and user-friendly interface.

The study also covered the principles of using Cron, including its configuration, syntax, and available alternatives that offer additional functionality or simplified management.

During the practical part, various tasks were scheduled on a Linux virtual machine. These included executing commands at specific times, running daily automated operations, scheduling tasks based on certain days or time intervals, and configuring periodic executions.

Furthermore, an alternative scheduling tool was installed and tested to perform similar operations. This demonstrated that Linux offers a wide range of powerful solutions for task automation and efficient system management.
